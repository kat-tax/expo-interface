# Theming

Colors follow the system's light or dark scheme and take a tint from the
`AccentProvider` seed, so a screen looks native on each platform without any
per-platform styling. There are two ways to read a color: `theme` in styles
and `useColor` everywhere else.

## Accent

`AccentProvider` takes a single hex `seed` (default `#007AFF`) and applies it
everywhere:

- **Android** generates a full Material 3 palette from the seed (the Material
  You algorithm) through the Compose `Host`.
- **iOS** applies the seed verbatim as the SwiftUI tint, like a single-color
  `AccentColor` asset.
- **Web** emits the seed as the `--color-tint` custom property; a runtime seed
  overrides it inline so every CSS consumer updates without re-rendering.

```tsx
<AccentProvider seed="#8959EA">
  <App/>
</AccentProvider>
```

`useAccentSeed()` returns the active seed and `onAccent(seed)` the black or
white contrast color for content drawn on top of it.

## `useColor`

Returns a color token as a plain string that tracks the active scheme and
accent. Use it for props that won't accept a platform color object from
`theme`, such as symbol tints or `@expo/ui` components:

```tsx
import {SymbolView} from 'expo-symbols';
import {useColor} from 'expo-interface';

const tint = useColor('tint');

<SymbolView name="star" tintColor={tint}/>
```

## `theme`

A static object with one entry per color token. Each entry is a platform
color reference: `PlatformColor` on iOS, a theme attribute on Android, a CSS
variable on web. The OS resolves the actual value and updates it when the
scheme changes, with no re-render required:

```tsx
import {theme} from 'expo-interface';

<View style={{
  backgroundColor: theme.backgroundElement,
  borderColor: theme.separator,
}}/>
```

## `usePalette`

Returns the resolved palette of the current scheme as plain color strings on
every platform, with the live accent as `tint`. `useColor` stays the right
call for styles (on web it hands out the CSS variable, which follows the
scheme without a re-render); `usePalette` is for canvases, native views and
anything else that cannot read a variable.

## Color scheme

`useColorScheme()` answers `'light'` or `'dark'` from one stable
subscription; every kit component follows it. `setColorScheme('system' |
'light' | 'dark')` forces a scheme or follows the system again:
`Appearance.setColorScheme` natively, and on web the forced palette written
on the root element with `color-scheme` and `data-theme`, remembered in
`localStorage` so `getThemeBootScript()` in `+html.tsx` applies it before
the bundle runs (`getThemeCSS()` carries the matching `:root[data-theme]`
palettes).

```tsx
import {getThemeBootScript, getThemeCSS} from 'expo-interface';

<style dangerouslySetInnerHTML={{__html: getThemeCSS()}}/>
<script dangerouslySetInnerHTML={{__html: getThemeBootScript()}}/>
```

## Layout and type constants

| Export | Purpose |
| --- | --- |
| `useNavTheme()` | React Navigation theme built from the palette and accent |
| `getThemeCSS()` | Palette as CSS variables, for `+html.tsx` |
| `getThemeBootScript()` | Script applying a saved forced scheme before the bundle runs, for `+html.tsx` |
| `useColorScheme()`, `setColorScheme()` | The scheme as a store, and forcing it |
| `usePalette()` | Resolved palette as plain colors |
| `colors` | Raw light and dark palettes |
| `spacing`, `bound`, `inset` | Layout constants |
| `fonts`, `fontWeights`, `variants` | Type constants |

`spacing` is a small scale (`half`, `one` … `six`, from 2 to 64 points),
`bound.contentMaxWidth` caps content at 800 points on wide screens, and
`inset` carries the per-platform top bar and bottom tab heights that `Screen`
pads for.
